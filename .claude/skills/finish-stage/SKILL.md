# Завершение этапа

Аргумент — номер PR (`$ARGUMENTS`); если не передан, возьми PR текущей ветки (`gh pr view --json number`). План этапа — `docs/plans/stage-*.md`, на который ссылается PR.

Шаги идут по порядку; на любой неудаче остановись и расскажи пользователю, что именно не прошло.

## 1. CI

- [ ] `gh pr checks N` — все проверки зелёные. Красные или ещё идущие — стоп: merge не делать, показать список.
- [ ] `gh pr view N --json mergeable,reviewDecision,state` — PR открыт и сливается без конфликтов.

## 2. Merge

- [ ] `GH_PROMPT_DISABLED=1 gh pr merge N --merge --delete-branch`
- [ ] `git switch master && git pull`
- [ ] Убедись, что рабочее дерево чистое и `git log -1` — merge-коммит этого PR.

## 3. Запись в `docs/lab-journal.md`

Допиши в конец файла секцию (формат — как у существующих записей: `## <дата> · <заголовок>`):

```
## <YYYY-MM-DD> · Этап N: <название>
Сделано: <что вошло, 2–4 строки, со ссылкой на PR>
Сломалось: <что падало по пути: сборка, CI, ревью, неверные допущения плана; «ничего», если так>
Уроки: <по пункту на урок, каждый — правило, применимое к следующему этапу>
```

Источники: план этапа, `git log master..` до merge (коммиты правок по ревью), замечания ревью в PR (`gh pr view N --comments`), прогоны `scripts/check.sh`. Не выдумывай: если факта нет в этих источниках — спроси пользователя.

## 4. Закрепление уроков

Для **каждого** урока предложи, куда его закрепить, и спроси пользователя (AskUserQuestion, по одному вопросу на урок или группой до 4):

| Куда | Когда |
|---|---|
| `CLAUDE.md` | правило для любой работы в репозитории; короткое, проверяемое |
| скилл (`.claude/skills/`) | шаг или ловушка конкретного процесса (новая фича, новый пакет) |
| агент (`.claude/agents/`) | что ревьюеру или ui-checker стоит проверять |
| тест / `scripts/check.sh` | урок можно превратить в автоматическую проверку — предпочтительный вариант |
| никуда | единичный случай; остаётся только в журнале |

Для каждого урока дай рекомендацию и причину в одну строку. Применяй только то, что пользователь подтвердил; правки обвязки — отдельным коммитом (`.claude/`, `CLAUDE.md`, `scripts/`), не вместе с записью журнала.

## 5. Отметка в плане

В `docs/plans/stage-N-*.md` сразу под заголовком поставь строку:

```
**Статус: выполнен** — [PR #N](<url PR>), <YYYY-MM-DD>
```

Если строка уже есть (план был в работе) — замени её. Хук SessionStart (`.claude/hooks/session-context.sh`) ищет именно `Статус: выполнен`, так что формулировку не менять.

## 6. Коммит

Push в `master` запрещён, поэтому запись журнала, отметка плана и подтверждённые правки обвязки идут через ветку `finish-stage-N`: коммиты, push, `gh pr create`. Этот PR сам не мержи.
